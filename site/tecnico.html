Como o sistema guarda e calcula

O modelo de dados que sustenta o estoque e a previsão, e os caminhos de backend que o grupo está avaliando.

  • USUARIO 1 → N MOVIMENTACAOo usuário registra movimentações

Como o estoque é calculado

Estoque do produto = soma das entradas − vendas − perdas. Não existe campo "estoque atual" para ficar desatualizado: o número sai sempre das movimentações.

Como a previsão usa os dados

Soma as movimentações do tipo VENDA dos últimos 30 dias de cada produto, divide por 30 e compara com o estoque e com a menor validade dos lotes.

Tecnologia: três caminhos possíveis

O backend ainda não foi escolhido. Todas as opções cabem em um projeto acadêmico. A decisão depende do que o grupo já domina.

OpçãoPontos fortesPontos de atenção
Python: Flask + SQLAlchemy + SQLiteBanco em um único arquivo, sem servidor. Combina com a matéria de modelagem. Fácil escrever a previsão em Python.Telas em HTML/Jinja exigem cuidado para ficarem simples. Hospedar para demonstração dá algum trabalho.
Node: Express + SQLiteMesma linguagem no front e no back. Muito material e exemplos.Só vale se o grupo já conhece JavaScript no servidor.
Serviço pronto: Supabase ou FirebaseBanco, login e API já prontos. Rápido para colocar online.Menos aprendizado de back-end. Depende de serviço externo e de conta do grupo.

Para decidir: escolha o que pelo menos dois integrantes já usaram. Em prazo curto, familiaridade vale mais que a tecnologia da moda.
